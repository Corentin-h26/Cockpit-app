Règles Firestore à AJOUTER dans le projet Firebase "reco-app-da0ce"
(le même projet que Recos) — Firebase Console > Firestore Database > Règles.

Ce projet a déjà des règles pour les collections de Recos (users/{uid}/...).
NE PAS les supprimer : coller les blocs ci-dessous À L'INTÉRIEUR du même
"match /databases/{database}/documents { ... }", à côté des règles
existantes, puis Publier.

MISE À JOUR (contrôle du contenu des lignes) : si les blocs Cockpit ci-dessous
sont déjà publiés, il suffit de
  1. AJOUTER les deux fonctions cockpitNombre() et cockpitLigneValide(),
  2. REMPLACER le bloc "match /cockpit_semaines/{docId}" par la nouvelle version,
puis Publier. Rien d'autre ne change.

--------------------------------------------------------------------

    function cockpitEstCapfinances() {
      return request.auth != null
        && request.auth.token.email is string
        && request.auth.token.email.matches('.*@capfinances[.]fr$');
    }
    function cockpitEstAdmin() {
      return request.auth != null
        && request.auth.token.email == 'c.hodicq-mandataire@capfinances.fr';
    }

    // Un chiffre de saisie : un vrai nombre, pas de texte, pas de valeur absurde.
    function cockpitNombre(v) {
      return v is number && v >= 0 && v <= 10000000;
    }

    // Contenu d'une ligne "semaine" : bon type et bonne taille pour chaque champ.
    // Sert de garde-fou côté serveur (l'appli échappe déjà tout ce qu'elle affiche) :
    // un compte ne peut plus écrire du texte à rallonge, du HTML dans un champ
    // chiffré, ou des dizaines de champs inventés.
    function cockpitLigneValide(d) {
      return d.keys().size() <= 30
        && d.semaine is string && d.semaine.size() <= 10
        && d.conseiller is string && d.conseiller.size() <= 80
        && cockpitNombre(d.get('rdv_poses', 0))
        && cockpitNombre(d.get('visio', 0))
        && cockpitNombre(d.get('r1', 0))
        && cockpitNombre(d.get('r2', 0))
        && cockpitNombre(d.get('suivis', 0))
        && cockpitNombre(d.get('potentiel', 0))
        && cockpitNombre(d.get('rdv_vus', 0))
        && cockpitNombre(d.get('visio_vues', 0))
        && cockpitNombre(d.get('r1_vus', 0))
        && cockpitNombre(d.get('r1_en_r2', 0))
        && cockpitNombre(d.get('r2_vus', 0))
        && cockpitNombre(d.get('r2_signes', 0))
        && cockpitNombre(d.get('suivis_faits', 0))
        && cockpitNombre(d.get('commissions', 0))
        && cockpitNombre(d.get('recommandations', 0))
        && (d.get('ressenti', null) == null
            || d.ressenti in ['Excellente', 'Bonne', 'Moyenne', 'Décevante', 'Très mauvaise'])
        && d.get('accompagnement', []) is list
        && d.get('accompagnement', []).size() <= 7
        && d.get('accompagnement', []).hasOnly(
             ['Technique', 'Commercial', 'Organisation', 'Prospection', 'Produits', 'Urgent', 'Pas de besoin']);
    }

    match /cockpit_roster/{docId} {
      allow read: if cockpitEstCapfinances();
      allow write: if cockpitEstAdmin();
    }

    match /cockpit_parametres/{docId} {
      allow read: if cockpitEstCapfinances();
      allow write: if cockpitEstAdmin();
    }

    match /cockpit_semaines/{docId} {
      allow read: if cockpitEstCapfinances();
      allow create: if cockpitEstCapfinances()
        && request.resource.data.ownerEmail == request.auth.token.email
        && cockpitLigneValide(request.resource.data);
      // L'administrateur peut tout modifier (réattribution, renommage d'un conseiller…).
      // Un conseiller ne modifie que ses lignes, sans changer de propriétaire, avec un contenu valide.
      allow update: if cockpitEstAdmin()
        || (cockpitEstCapfinances()
            && resource.data.ownerEmail == request.auth.token.email
            && request.resource.data.ownerEmail == resource.data.ownerEmail
            && cockpitLigneValide(request.resource.data));
      allow delete: if cockpitEstAdmin()
        || (cockpitEstCapfinances() && resource.data.ownerEmail == request.auth.token.email);
    }

Ce que ça garantit :
- Lecture : tous les comptes @capfinances.fr (lecture d'équipe, comme avant).
- Roster (Équipe) et Paramètres (pondération) : écriture réservée à
  c.hodicq-mandataire@capfinances.fr.
- Semaines (Ma semaine / Ma fiche) : chacun ne peut créer/modifier/supprimer
  que ses propres lignes (ownerEmail = l'email du compte qui a créé la
  ligne) ; l'administrateur peut tout modifier.
- Contenu des lignes (nouveau) : semaine ≤ 10 caractères, nom ≤ 80 caractères,
  tous les chiffres sont de vrais nombres entre 0 et 10 000 000, le ressenti et
  l'accompagnement ne prennent que les valeurs proposées par l'appli, et une
  ligne ne peut pas changer de propriétaire (sauf par l'administrateur).

Vérifier après publication :
- Ouvrir l'appli, modifier un chiffre dans "Ma semaine" : ça doit s'enregistrer
  comme avant (voyant "Synchronisé").
- Si un conseiller voit "Enregistrement refusé" en haut à droite, c'est qu'une
  valeur sort de ces limites (chiffre négatif, nom très long…).
- Firebase Console > Firestore > Règles > "Simulateur de règles" permet de tester
  une écriture sans toucher aux données.
